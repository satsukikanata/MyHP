# PR の中身を作る

渡された PR のブランチに切り替え、plan.md を今のコードと照らして見直し、そのまま plan.md の順に作る。作ったものは同じ PR に積む(新しい PR は作らない)。

## 1. PR のブランチに切り替える

1. 頼みの中から PR の URL(`https://github.com/<持ち主>/<リポジトリ>/pull/<番号>`)を探す。無ければ、URL を貼ってもらうよう頼んで止まる
2. `git remote get-url origin` が、URL の `<持ち主>/<リポジトリ>` と同じか確かめる。違えば、そう言って止まる
3. `git status --short` で、まだ commit していない変更が無いか見る。あれば、どのファイルかを見せて止まって聞く(消したり、しまったりしない)
4. PR のブランチ名を調べる
   - `git ls-remote origin refs/pull/<番号>/head` で出た英数字(コミットの ID)と同じものを、`git ls-remote --heads origin` の中から探す。その行の `refs/heads/` の後ろがブランチ名
   - 見つからない・2つ以上あるときは、PR の URL を開いてブランチ名を読む。それでも分からなければ、PR のページにあるブランチ名を貼ってもらうよう頼んで止まる
5. `git fetch origin` → `git switch <ブランチ名>` → `git pull --ff-only`。すでに手元にあるブランチでも、必ず pull する(講師や相談役の直しが GitHub 側に積まれていることがある)。pull が失敗したら(GitHub 側のブランチが作り直されたときなど)、自分で直さずに、出た文を見せて止まって聞く
6. `git merge-base --is-ancestor HEAD origin/main` が成功したら、この PR はもう main に入っている。そう言って止まる

## 2. 読む

7. `git diff --name-only origin/main...HEAD` で、この PR で変わったファイルを見る。その中の `specs/<番号>-<名前>/` が、この周のフォルダ(ブランチ名とフォルダ名は違うことがある)。見つからない・2つ以上あるときは止まって聞く
8. そのフォルダの intent.md・spec.md・plan.md と、README.md・AGENTS.md を読む。同じフォルダに mock.html があれば、見た目の手本にする。mock.html と spec.md が違うところは spec.md に従う。plan.md が無ければ、spec.md と今のコードから書いて commit する

## 3. plan.md を見直す

9. plan.md の各ステップの「変える場所」が今のコードに本当にあるか、そこを変えれば足りるか(他にも変える場所がないか)を見る
10. 一度に全部作る順番なら、ブラウザで確かめられる区切りに分ける
11. 合わないところだけ plan.md を直して commit する。直すところが無ければ commit しない
12. plan.md と spec.md の中身(数・完成の条件など)が違っていたら、どちらに合わせるかを決めずに、コードを変える前に止まって聞く。答えをもらったら、spec.md と plan.md をその答えにそろえて commit し、続ける
13. 作るのに要るファイル(画像など)がリポジトリに無ければ、コードを変える前に止まって、どこにあるかを聞く。仮の画像を作ったり、PC の中を探したりしない
14. spec.md に無いことで決める必要があるものが見つかったら、決めずに、コードを変える前にそこで止まって聞く
    - 聞き方: 1回に3つまで。番号を付け、それぞれにおすすめの答えを1つ添える(一番小さく作れる案)
    - 答えをもらったら、spec.md の最後の「決めたこと」に足して commit し、続ける

## 4. 作る

15. 聞くことが無ければ、plan.md の順に作る。前の会話で途中まで作ってあれば(plan.md のステップの commit があれば)、続きから作る
16. ステップごとに、ページをブラウザで開くなどして確かめ、commit する
17. 全部できたら push する。新しいブランチと PR は作らない。マージもしない(マージは本人が画面で確かめてから押す)

## 5. 報告する

18. 次の3つを、短い日本語で報告する
    - どのファイルに何をしたか
    - spec.md の完成の条件ごとに「どう確かめたか・結果」。確かめられなかったものは、そう書く
    - 本人が画面で確かめるところ(どのファイルをブラウザで開き、どこを見るか)

## してはいけないこと

- main で作業しない・main に push しない
- `git push --force`・`git reset --hard`・フォルダやファイルをまとめて消す、をしない。うまくいかないときは止まって聞く
- 頼まれていないところ(見た目・文章・ファイル)は変えない
