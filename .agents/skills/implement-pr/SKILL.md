# PR の中身を作る

渡された PR のブランチに切り替え、plan.md を今のコードと照らして見直し、そのまま plan.md の順に作る。作ったものは同じ PR に積む(新しい PR は作らない)。

## 1. PR のブランチに切り替える

切り替えは、この Skill のフォルダにあるスクリプトで行う。git のコマンドを自分で組み立てて切り替えない。

1. 頼みの中から PR の URL(`https://github.com/<持ち主>/<リポジトリ>/pull/<番号>`)を探す。無ければ、URL を貼ってもらうよう頼んで止まる
2. リポジトリの一番上のフォルダで、次を動かす

   ```
   powershell -NoProfile -ExecutionPolicy Bypass -File .agents/skills/implement-pr/scripts/switch-to-pr.ps1 <PR の URL>
   ```

   スクリプトがすること: URL のリポジトリがこのフォルダのものか確かめる → commit していない変更があれば止まる → PR のブランチ名を調べる → GitHub の最新を取ってきて切り替える(手元にあれば早送りで取り込む) → もう main に入った PR なら止まる → この PR で変わった `specs/<番号>-<名前>/` を探す
3. 最後の行を見る
   - `RESULT: OK` なら、`BRANCH:`(切り替えたブランチ)と `SPEC_DIR:`(この周のフォルダ)を控えて、「2. 読む」に進む
   - `RESULT: STOP` なら、`STOP:` の行の理由と、その下の行を、短い日本語にして見せて止まる。自分で直したり、別のやり方で切り替えたりしない
   - ブランチ名が分からないと言われたときだけ、PR のページにあるブランチ名を聞き、最後に `-Branch <ブランチ名>` を付けて動かし直す
   - スクリプト自体が動かない(見つからない・エラーで止まる)ときも、出た文を見せて止まる

## 2. 読む

4. `SPEC_DIR:` のフォルダの intent.md・spec.md・plan.md と、README.md・AGENTS.md を読む。同じフォルダに mock.html があれば、見た目の手本にする。mock.html と spec.md が違うところは spec.md に従う。plan.md が無ければ、spec.md と今のコードから書いて commit する

## 3. plan.md を見直す

5. plan.md の各ステップの「変える場所」が今のコードに本当にあるか、そこを変えれば足りるか(他にも変える場所がないか)を見る
6. 一度に全部作る順番なら、ブラウザで確かめられる区切りに分ける
7. 合わないところだけ plan.md を直して commit する。直すところが無ければ commit しない
8. plan.md と spec.md の中身(数・完成の条件など)が違っていたら、どちらに合わせるかを決めずに、コードを変える前に止まって聞く。答えをもらったら、spec.md と plan.md をその答えにそろえて commit し、続ける
9. 作るのに要るファイル(画像など)がリポジトリに無ければ、コードを変える前に止まって、どこにあるかを聞く。仮の画像を作ったり、PC の中を探したりしない
10. spec.md に無いことで決める必要があるものが見つかったら、決めずに、コードを変える前にそこで止まって聞く
    - 聞き方: 1回に3つまで。番号を付け、それぞれにおすすめの答えを1つ添える(一番小さく作れる案)
    - 答えをもらったら、spec.md の最後の「決めたこと」に足して commit し、続ける

## 4. 作る

11. 聞くことが無ければ、plan.md の順に作る。前の会話で途中まで作ってあれば(plan.md のステップの commit があれば)、続きから作る
12. ステップごとに、ページをブラウザで開くなどして確かめ、commit する
13. 全部できたら push する。新しいブランチと PR は作らない。マージもしない(マージは本人が画面で確かめてから押す)

## 5. 報告する

14. 次の3つを、短い日本語で報告する
    - どのファイルに何をしたか
    - spec.md の完成の条件ごとに「どう確かめたか・結果」。確かめられなかったものは、そう書く
    - 本人が画面で確かめるところ(どのファイルをブラウザで開き、どこを見るか)

## してはいけないこと

- main で作業しない・main に push しない
- `git push --force`・`git reset --hard`・フォルダやファイルをまとめて消す、をしない。うまくいかないときは止まって聞く
- 頼まれていないところ(見た目・文章・ファイル)は変えない
